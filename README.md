# Wakeon

> **대답이 늦어지면, 차가 먼저 묻습니다. "혹시 졸리세요?"**  
> Pleos 음성 AI와의 상호작용으로 졸음 신호를 확인하고, "응" 한 마디로 졸음쉼터 경유와 15분 휴식까지 이어 주는 졸음방지 케어 Pleos 서비스입니다.

현대자동차·기아 Pleos Connect 차량용 앱 공모전 출품작입니다. 팀 wakeoneteam.

## 1. 앱 이름과 한 줄 소개

- 앱 이름: **Wakeon** (음성 호출어: "웨이크온")
- 한 줄 소개: 대답이 늦어지면, 차가 먼저 묻습니다. "혹시 졸리세요?" Pleos 음성 AI와의 상호작용으로 졸음 신호를 확인하고, "응" 한 마디로 졸음쉼터 경유와 15분 휴식까지 이어 주는 졸음방지 케어 Pleos 서비스입니다.
- 졸음을 진단하는 앱이 아니라 쉬게 돕는 앱입니다. 대화 중 대답이 평소보다 느려지면 졸린지 직접 묻습니다. 운전자가 "응" 한 마디만 하면 졸음쉼터를 경유지로 넣고, 15분 휴식과 다시 출발하기 전 확인까지 이어 줍니다.

## 2. 실행 방법

### 가. APK를 설치해 직접 써 보기

1. Android Studio에서 Pleos Connect 에뮬레이터 v2.1.0을 Cold boot로 켭니다.
2. APK를 설치합니다.
   ```
   adb install apk/wakeoneteam_Wakeon_release.apk
   ```
3. 앱 목록에서 **Wakeon**을 엽니다. 첫 화면은 동의 화면입니다. **동의하고 시작**을 누르면 시스템 권한 창이 두 번 뜨는데, 둘 다 **허용**을 누릅니다.
   - "위치 정보" 창: 차량 속도 권한(`CAR_SPEED`)입니다. 이 에뮬레이터는 속도 권한을 위치 권한으로 묻습니다.
   - "오디오를 녹음" 창: 마이크 권한입니다.
4. 홈 화면에서 **출발 전 체크 · 30초**를 누르면, 앱이 질문 4개로 평소 반응 속도를 잽니다.
5. 기어와 속도는 Pleos Connect Virtual Console에서 바꿉니다([공식 안내](https://document.pleos.ai/en/docs/pleos-only/app-test-guide/virtual-console-guide)). 기어를 D로 바꾸면 주행 대기 화면으로 넘어갑니다. 연속 2시간 주행처럼 시간이 오래 걸리는 조건은 아래 나.의 시연 신호로 확인하는 것이 빠릅니다.
6. 주행 화면은 1:1(세로) 창을 기준으로 만들었습니다. 앱 창 오른쪽 끝의 손잡이(⋮)를 왼쪽으로 끌면 1:1 창이 됩니다.

### 나. 시연 영상과 같은 흐름 재생하기

운전자의 대답, 응답 시간, 시계, 연속 주행 시간은 직접 만들기 어렵습니다. 그래서 `adb` 시연 신호로 넣고, 그 신호를 바탕으로 판단하고 상태를 바꾸는 일은 앱이 그대로 합니다. 화면에는 시연용 버튼이나 표시가 없습니다.

1. 에뮬레이터를 켭니다. 이 스크립트는 차량 음량(음성·알람)도 40/45로 맞춥니다.
   ```
   bash demo/start_emulator.sh
   ```
   내비가 "서비스 연결 중입니다"에서 넘어가지 않으면(에뮬레이터가 맥의 DNS를 못 읽는 경우) DNS를 지정해 켭니다.
   ```
   DNS_SERVER=8.8.8.8,1.1.1.1 bash demo/start_emulator.sh
   ```
2. 위 가.의 2~3번처럼 앱을 설치하고 한 번 동의합니다.
3. 장면 1~22를 순서대로 재생합니다. 약 4~5분 걸립니다.
   ```
   bash demo/run_scenario.sh --skip-nav-check
   ```
   스크립트는 시연 신호와 함께 Virtual Console에도 같은 기어·속도·브레이크 값을 넣습니다. 그래서 왼쪽 시스템 주행 화면과 앱이 같은 값을 보입니다. 방향지시등은 앱에만 시연 신호로 넣습니다(시스템 방향지시등을 켜면 에뮬레이터가 측면 카메라 창을 앱 위에 띄웁니다). 시작 전에 내비가 지도 서버에 붙었는지 보고, 붙었으면 목적지 부산역을 넣습니다. `--skip-nav-check`를 붙이면 내비가 연결되지 않아도 그대로 진행합니다.
4. 신호를 하나씩 보낼 수도 있습니다. 예:
   ```
   adb shell am broadcast -a com.wakeon.app.DEMO -p com.wakeon.app --es gear D --ei speed 98
   ```
   신호 목록은 [`docs/DEMO_SCENARIO.md`](docs/DEMO_SCENARIO.md) 3장, 장면표는 2장에 있습니다.

## 4. 사용한 Pleos Connect 에뮬레이터 버전과 화면 규격

- 에뮬레이터: **Pleos Connect v2.1.0** (`ro.build.display.id` = `RELEASE.release_connect_v2.1.0`)
- 디스플레이: 2560×1440 px, 160 dpi (1dp = 1px)
- 설계 기준(공식 규격표): 세로 창 840×1184 dp, 가로 창 1700×1184 dp
- 에뮬레이터에서 앱이 실제로 받은 창(앱 로그 `window content`로 측정)
  - 2:0 가로 창: **1682×1210 dp**. 정차 화면(동의, 홈, 출발 전 체크, 도착, 휴식, 다시 출발하기 전 확인)에 씁니다.
  - 1:1 세로 창: **841×1210 dp**. 주행 화면(주행 대기, 대화, 대화 멈춤, 졸린지 확인, 경고, 쉼터 제안, 경유지 안내)에 씁니다.
- 화면을 고정 픽셀로 배치하지 않았습니다. 받은 창 크기에 맞춰 늘고 줄며, 주행 화면은 가로 창에서도 세로 배치 그대로 가운데에 놓입니다.

## 1차 제출에 담은 기능 (시연 영상 장면 1~21)

1. **출발 전 체크**: 졸린 정도(1~9)와 간단한 셈 문제로 오늘 평소 반응 속도(기준선)를 잽니다.
2. **먼저 말 걸기**: 연속 2시간 주행 같은 조건이 되면 짧은 대화를 걸고, 대답까지 걸린 시간을 잽니다.
3. **대화 멈춤**: 브레이크나 방향지시등을 쓰면 하던 말을 바로 멈추고 조용히 있다가, 10초 뒤에 이어서 말합니다.
4. **졸린지 확인**: 대답이 기준선보다 많이 느려지면 "혹시 졸리세요?"라고 묻습니다. 대답이 없으면 한 번 더 묻습니다.
5. **단계적 경고**: 그래도 대답이 없으면 알림음을 1단계에서 3단계까지 울리고, 쉼터로 안내하겠다고 말합니다.
6. **쉼터 제안과 경유지**: 가장 가까운 졸음쉼터까지 거리와 시간을 말하고, "응"이라고 하면 경유지로 넣습니다. 1km 전에 한 번 더 알립니다.
7. **도착과 15분 휴식**: 도착하면 15분 휴식을 제안합니다. 휴식 중에는 화면을 어둡게 하고 남은 시간을 큰 타이머로 보여 줍니다. 끝나기 전 미리 알림 없이 끝까지 쉬게 하고, 시간이 되면 알람과 음성("일어나실 시간이에요. 15분 휴식 완료. 등받이를 세워 주세요.")으로 깨웁니다. 알람은 30초마다 한 단계씩 커져 3단계까지 오릅니다.
8. **다시 출발하기 전 확인**: 짧은 질문 3개로 반응 속도를 다시 보고, 다음 쉼터까지 거리를 알려 줍니다. 화면에는 "기어를 D로 바꾸면 대기 상태로 돌아가요 · 연속 주행 시간 0부터"를 안내합니다.

화면에 나오는 글자와 음성으로 말하는 문장은 같은 대사 목록에서 가져옵니다. 단위 테스트가 두 가지를 검사합니다. 하나는 모든 대사와 화면 문구에 금지 표현(예: "위험합니다")이 없는지, 다른 하나는 주행 화면의 문구가 한 덩어리 3줄·120자 이하인지입니다.

## 알려진 한계

- **대답 입력**: 시연 영상의 운전자 대답은 시연 신호로 넣었고, 영상에는 자막으로 보입니다. 앱은 Pleos SpeechToText로 듣도록 만들었습니다. 다만 1차 제출에서는 에뮬레이터 마이크로 실제 음성 인식이 되는지 끝까지 확인하지 못했습니다.
- **내비 지도와 경유지**: 시연 영상의 내비는 부산역 경로를 안내하지만, 지도 바탕 그림은 하얀 채로 비어 있습니다(원인 미확인). 앱은 NaviHelper로 쉼터를 경유지로 추가하도록 요청합니다. 영상에서도 내비가 "경유지 1개 포함" 경로를 보여 줍니다. 다만 내비의 확인 신호가 요청 7초 뒤에 와서 앱의 대기 시간(5초)을 넘겼습니다. 그래서 앱은 확인을 기다리지 않고 자기 화면에 경유지를 표시하며 진행했습니다.
- **안전벨트 경고**: 정차 장면의 왼쪽 시스템 화면에 "안전 벨트를 매세요."가 보입니다. Virtual Console에 벨트 체결 값이 없어서 끌 수 없었습니다.
- **차량 제어 없음**: 시트·조명·공조는 제어하지 않습니다. "등받이를 세워 주세요"처럼 음성으로 안내합니다.
- **쉼터 데이터**: 시연 경로의 쉼터 3곳은 공공데이터에서 골라 앱에 넣어 두었습니다(`app/src/main/assets/demo_route.json`).
- 음성 원본은 저장하지 않습니다. 기록에는 응답 시간(ms)과 대답의 뜻(응/아니 등)만 남습니다.

## 2차 계획 (1차 영상에 없음)

- 공공데이터로 쉼터 정보를 실시간으로 받아 오기, 대화 주제 늘리기
- 정차 화면의 가로/세로 전환 완성도, 축소 모드·정차 전용 모드
- 휴식 중 몸 깨우기 루틴(지금은 버튼만 보이고 동작하지 않습니다)
- Pleos 차량 제어가 열리면 시트·조명·공조를 함께 조정하기
- 앱 창이 가려져도 타이머와 음성이 계속 돌게 하기

## 저장소 구성

| 경로 | 내용 |
| --- | --- |
| `app/` | 안드로이드 앱 (`core/WakeonStateMachine.kt`가 모든 판단과 상태 전이를 맡습니다) |
| `demo/` | 에뮬레이터 실행, 시연 시나리오, 녹화 스크립트 |
| `docs/` | 기획(PRD), 동작 기준(SPEC), 시연 시나리오, 디자인 차이, 결정 기록, 작업 기록 |
| `tools/` | release APK 만들기(`release.sh`), 소리 검사 도구 |
| `apk/` | 제출용 release APK |

Wakeon은 졸음을 진단하지 않으며, 운전자의 주의 의무를 대신하지 않습니다. 졸리면 바로 안전한 곳에서 쉬세요.
