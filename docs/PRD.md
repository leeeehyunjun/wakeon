# Wakeon PRD

Nov 8, 2026 · @어식스트

## 1. 개요

**한 줄 피치:** 졸음이 오기 쉬운 순간 차가 먼저 말을 걸고, 가장 가까운 졸음쉼터까지 데려가 15분 동안 제대로 쉬게 하는 Pleos 음성 동반자.

Wakeon은 **졸음 감지기가 아니라 휴식 동반자**입니다. 차가 "쉬세요"라고 경고한 뒤 비어 있는 단계, 즉 다시 말을 걸어 깨워 두고, 쉼터를 고르고, 경로에 넣고, 쉬게 하고, 출발 전에 다시 확인하는 흐름을 대신 맡습니다.

| 항목 | 내용 |
| --- | --- |
| 공모전 | 현대자동차그룹 차량용 앱 개발 공모전, 대학생 부문 |
| 마감 | 1차 서류 11/15, 2차 PT·실제 동작 시연 12/3\~4 |
| 플랫폼 | Pleos Connect(안드로이드 오토모티브 기반), 그랜저·아반떼 |
| 카테고리 | 모빌리티 서비스 (주행 중 제한적 사용이 명시된 카테고리) |
| 쓰는 SDK | Vehicle(상태 조회)·NaviHelper는 사용 가능. TextToSpeech·SpeechToText는 Pleos SDK 우선, 안 되면 안드로이드 기본 음성. 위치는 NaviHelper와 안드로이드 기본 위치(FusedLocation·Vehicle Control은 Pleos 콘솔 ‘준비 중’, 11/12 확인) |

**보도자료 요약 (가상):** "현대차 그랜저, 이제 ‘쉬세요’에서 끝나지 않는다." 밤 11시 경부고속도로, 출발 2시간째 운전자에게 Wakeon이 "점심에 뭐 드셨다고 하셨죠?"라고 묻습니다. 대답이 평소보다 늦어지자 "혹시 졸리세요?"라고 다시 묻고, 대답이 없으면 경고음이 차츰 커집니다. "12km 앞 ○○졸음쉼터를 경유지로 넣을까요?" → "응." 쉼터에서 기어를 P에 넣으면 15분 알람이 맞춰지고 "등받이를 젖히고 눈을 붙이세요"라고 안내합니다. 알람이 울리면 "등받이를 세워 주세요"라고 안내하고, 출발 전 짧은 반응 체크를 합니다.

## 2. 문제와 근거

**문제 정의:** 운전자는 졸음을 느끼거나 차의 경고를 받아도 **어디서, 얼마나, 어떻게 쉬어야 하는지를 운전하면서 스스로 정해야 하고**, 그사이 대개 계속 달린다.

| 근거 | 내용 | 출처 |
| --- | --- | --- |
| 졸음운전은 치명적 | 2019\~2023년 사고 10,765건, 사망 316명. 사고 100건당 사망 2.9명으로 음주운전(1.5명)의 약 2배, 고속도로는 8.3명 | [SBS Biz·경찰청](https://biz.sbs.co.kr/amp/article/20000165015) |
| 고속도로 사망의 다수 | 2026년 상반기 고속도로 사망 95명 중 졸음·주시태만 68명(71.6%). 주시태만이 합쳐진 수치 | [파이낸셜뉴스](https://www.fnnews.com/news/202607281338101369) |
| 확실한 대책은 휴식뿐 | 카페인과 짧은 낮잠을 함께 쓰자 시뮬레이터 사고가 위약 대비 9%로 감소. 찬바람·라디오는 효과 없음 | [Reyner & Horne 1997](https://pubmed.ncbi.nlm.nih.gov/9401427/), [1998](https://www.ncbi.nlm.nih.gov/pubmed/9485532) |
| 졸음쉼터 효과 | 설치 후 사고 감소가 14\~58%로 보고됨(출처마다 크기 차이 큼) | [GHSA 2026](https://www.ghsa.org/sites/default/files/2026-02/Wake_Up_Call_2026_Update.pdf), [메트로신문](https://www.metroseoul.co.kr/article/20231001500001) |

| 대화의 효과 | 각성도가 낮을 때 짧게 배치한 언어 과제가 차선 유지를 개선. 단, 실제 도로 검증은 없음 | [Atchley & Chan 2011](https://kuscholarworks.ku.edu/bitstream/1808/7121/1/Atchley_Chan_Potential_abstract.pdf) |

**왜 차 안이어야 하나:** 휴대폰 앱은 기어 P를 판별하거나 내장 내비에 경유지를 넣을 수 없습니다. 차가 이미 아는 기어·속도·위치·경로 정보를 엮어 ‘휴식 결정 비용’을 차가 대신 집니다. 시트·조명 제어는 Pleos가 Vehicle Control을 열면 더하는 확장입니다.

## 3. 목표와 비목표

**목표**

- 졸음 위험이 있는 운전자를 **졸음쉼터에서 15분 이상 쉬게** 만든다.
- 차의 경고 이후 비어 있는 단계(다시 말 걸기 → 쉼터 안내 → 휴식 → 재출발 확인)를 하나의 흐름으로 잇는다.
- 주행 중에는 시선 요구 0회, 음성만으로 동작한다.

**비목표 (v1에서 하지 않을 것)**

- 졸음·수면장애 진단, 카메라·시선 추적
- 자동 긴급 전화, 운전 차단
- 현대 DAW·EU DDAW·NCAP과 동등하다는 주장
- 음성으로 사람 식별, 음성 원본 저장
- 주행 중 영상·게임, 차량 진동(API 없음)

**원안에서 바뀐 점**

| 원안 | 바뀐 설계 | 이유 |
| --- | --- | --- |
| 응답 2초 늦으면 의심, 3초면 경고 | 운전 초반에 잰 **본인 평소 응답 속도** 대비 지연 + 무응답 + 오답 + 본인 응답을 종합. 2초·3초는 평소 속도를 재기 전 임시값 | 고정 기준을 뒷받침하는 연구가 없고, 막히는 구간의 늦은 대답은 정상 |
| "앞차 색깔은?" 같은 자유 대화의 맥락 이탈 판정 | 정답이 있는 질문(간단한 셈, 끝말잇기, 아까 한 대답 다시 묻기)으로 오답 판정. 자유 대화는 속도 측정용 | 차는 정답을 확인할 수 없음 |
| 경고음 + 조명 + 차량 진동 | 경고음 3단계(실내 조명은 Vehicle Control이 열리면 추가, 깜빡임 없이) | 진동 API 없음, 갑작스러운 큰 소리는 급조작 위험 |
| 도착 후 ‘휴식’과 ‘잠 깨기’ 동등 선택 | **휴식이 기본값.** 몸 깨우기(차와 함께하는 스트레칭, 따라 말하기)는 낮잠 뒤 회복 단계 | 확실한 대책은 휴식뿐, 운동은 효과가 거의 없음 |
| 친구·가족에게 전화 | P2, 정차 중에만 | Pleos 통화 기능 제한, 졸릴 때 통화는 오히려 위험 |
| 주차 브레이크로 도착 판단 | 기어 P + 속도 0 | Pleos 브레이크 API에 주차 브레이크 없음 |

## 4. 타깃과 포지셔닝

첫 공략층은 **장거리·야간 자가용 운전자**입니다. 규모와 빈도 수치는 모두 추정입니다.

| 세그먼트 | 문제 강도 | 규모(국내) | 사용 빈도 | 우선순위 |
| --- | --- | --- | --- | --- |
| 장거리·야간 자가용 운전자 | 높음(고속도로, 21\~06시) | Pleos 자가용 약 5.3\~5.9만 대 중 월 1회 이상 장거리 25\~40% (추정) | 월 1\~3회 (추정) | 1차 |
| 명절·휴가 귀성객 | 높음(10시간 이상 주행) | 추석 고속도로 하루 605\~684만 대 | 연 2\~4회 | 획득 캠페인 |
| 영업·외근직 | 중\~높음 | 집계 없음 | 주 단위 (추정) | 2차 |

**포지셔닝:** Wakeon은 현대 DAW를 대체하지 않고, **DAW가 ‘쉬세요’라고 말한 뒤 어디서·얼마나·어떻게 쉼지를 대신 정해 주는 층**입니다.

| 항목 | 현대 DAW · 기아 DDAW | 벤츠 ATTENTION ASSIST | Wakeon |
| --- | --- | --- | --- |
| 감지 | 조향·차선 패턴 또는 눈 카메라 | 운전 습관 학습, 60\~200km/h | 감지를 주장하지 않음. 대화 반응·본인 응답·주행 맥락을 보조 신호로 |
| 경고 이후 | 메시지와 경고음 한 번 | 휴게소 검색 제안, 15분 뒤 반복 | 다시 말 걸기 → 단계적 경고 → 쉼터 경유지 → 휴식 모드 → 재출발 확인 |
| 규제상 지위 | 차량 시스템 | 차량 시스템 | 인포테인먼트 앱(규제 대상 아님) |
| 관계 | - | - | 보완. DAW 신호는 읽을 수 없어 맥락과 사용자 요청으로 진입 |

가장 큰 경쟁 위험은 같은 플랫폼의 **글레오 AI**입니다. 현대가 기본 기능으로 ‘깨움 대화’를 넣으면 흡수될 수 있어, 차별점은 대화가 아니라 **쉼터 → 휴식 → 재출발 확인**까지 이어지는 흐름에 둡니다.

## 6. 단계별 상세

수치(분, 배수, 반경)는 모두 검증 전 출발값입니다. 차량 제어(`CONTROL_CAR_*`, 콘솔의 Vehicle Control)는 2026-11-12 기준 Pleos 콘솔에서 ‘준비 중’이라 신청할 수 없습니다. v1은 제어 없이 음성 안내로 동작합니다(D13).

| 단계 | 트리거 | 음성 예시 | SDK·API | 주행 상태 제약 | 실패 시 대체 |
| --- | --- | --- | --- | --- | --- |
| 0. 동의 | 첫 실행 | 고지 문구, 명시적 탭 동의 | UI | 정차 중에만 | 동의 없으면 정차 기능만 |
| 1. 출발 전 체크 | 기어 P에서 앱 활성 | "지금 졸린 정도를 1\~9로 말해 주세요", "7 더하기 5는요?" 3\~5문항 30초 | TTS, STT, 기어(표준 차량 API) | P 상태에서 진행 | 건너뛰면 주행 초반 대화로 평소 속도 수집 |
| 2. 위험 맥락 감시 | 연속 2시간 주행, 21\~06시·12\~15시, 70km/h 이상 10분, "웨이크온 켜줘" | (말하지 않고 대기) | 속도·기어, NaviHelper(선택) | - | 맥락 데이터 없으면 시간 기준만 |
| 3. 가벼운 대화 | 위험 점수가 기준을 넘음, 3\~5분 간격 | "점심 뭐 드셨어요?" / "끝말잇기 할까요? 기차" | TTS, STT(응답 시간 측정) | 음성만, 시선 0회. 브레이크·방향지시등·내비 안내·글레오 동작 중엔 멈춤 | 음성 인식 오류는 무응답으로 세지 않음 |
| 4. 의심 확인 | 최근 3번 중 2번이 평소의 1.5배 넘게 늦음, 오답 2회, 무응답 1회 | "혹시 졸리세요? ‘응’ 또는 ‘아니’로 말해 주세요" | TTS, STT(키워드) | 음성만 | ‘응’이면 1단계 알림음만 울리고 바로 쉼터 제안 |
| 5. 경고 | 연속 무응답 2회, 지연 지속 (본인 ‘응’은 1단계 알림음 후 바로 6단계로) | 경고음 3단계 + "졸음 신호가 보여요. 가까운 쉼터로 안내할게요" | 오디오 포커스(알람) | 내비 오디오 채널 사용 금지 | 소리가 막히면 한 줄 알림. 실내 조명은 Vehicle Control이 열리면 추가 |
| 6. 쉼터 제안·추가 | 5단계, 또는 4단계에서 ‘응’ | "12km 앞 ○○졸음쉼터를 경유지로 넣을까요?" | 졸음쉼터 공공데이터(253행, 진행 방향 필터) + 현재 위치(NaviHelper, 안 되면 안드로이드 위치) + NaviHelper 경유지 추가 | 음성으로 확인 | 내비 미지원이면 거리·방향을 음성 안내 |
| 7. 거절 처리 | ‘아니’, ‘괜찮아’ | "알겠어요. 15분 뒤에 다시 여쭤볼게요" | - | 완전히 끌 수는 없고 미루기만 | 다음 쉼터가 가까워지면 다시 제안 |
| 8. 도착·주차 판단 | 쉼터 도착 신호 또는 반경 150m 진입 **그리고** 기어 P·속도 0 | "도착했어요. 15분 쉬어 갈까요? 커피가 있으면 지금 드세요" (화면 카드: "위드라이브 앱이 있으면 15분 휴식으로 도로공사 휴식포인트를 받을 수 있어요(Wakeon 연동은 제휴 후)") | NaviHelper(경로·위치), 기어 | 정차 중에만 | 도착 신호가 없으면 근접 + P로 판단 |
| 9. 휴식 모드(기본값) | ‘쉴래’ 또는 10초 무응답 | "카페인 음료가 있으면 지금 드세요. 등받이를 젖히고 눈을 붙이세요." 15\~20분 알람 | 오디오(알람). 시트·조명·공조 제어는 Vehicle Control 준비 중이라 v1 제외 | 정차 중에만 | Vehicle Control이 열리면 등받이·조명·공조 자동 조절 추가 |
| 10. 몸 깨우기(회복 단계) | 알람 뒤, 또는 낮잠을 거절한 경우 | 음성으로 안내하는 스트레칭, 따라 말하기, "창문 열고 1분 걸어 볼까요?" | TTS, STT, 영상 | **영상은 정차 중에만**, 출발 시 즉시 중지 | 영상이 막히면 음성 스트레칭 |
| 11. 재출발 체크 | 휴식 끝, 또는 P→D 전환 시도 | "등받이를 세워 주세요" → 정답 질문 3개 → "반응이 아직 평소보다 느려요. 5분만 더 쉬어 가세요" 또는 "다음 쉼터는 ○ km 앞이에요" | TTS, STT | **출발 전에 등받이 세우기 확인**(음성 질문) | "운전해도 안전합니다" 문구 금지 |

## 9. 성공 지표

**North Star: 월간 ‘앱이 유도한 휴식 완료 건수’** — 앱의 제안으로 쉼터에 도착해 P 상태로 15분 이상 머문 건수입니다. 15분은 도로공사 휴식포인트 기준과 맞췄습니다. 경고 횟수나 대화 턴 수는 North Star가 아닙니다. 사용자를 짜증나게 할수록 올라가기 때문입니다.

추가 확인 사항: 에뮬레이터에 내비 앱이 있는지, GPS 경로 재생을 NaviHelper·안드로이드 위치가 따라가는지, 휴식 중 절전 상태에서 알람이 울리는지, 통화 연결 기능을 앱에서 불러올 수 있는지. 관련 문서: [Pleos 주행 제한 정책](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/driving-restiction-policy), [앱 카테고리](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/app-category), [NaviHelper 경유지](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/NaviHelper/waypoint-settings), [졸음쉼터 공공데이터](https://www.data.go.kr/data/15028203/fileData.do).

## 12. MVP 범위와 일정

11/15 서류에는 이 PRD와 에뮬레이터 음성 루프 검증 결과를, 12/3 데모에는 처음부터 끝까지 이어지는 흐름 하나를 담습니다.

| 항목 | 11/15 서류 | 12/3 데모 |

**데모 시나리오 (약 4분)**

1. **0:00 출발 전** — 기어 P, 출발 전 체크 3문항, 평소 속도 표시
2. **0:40 고속 주행** — 기어 D, 100km/h, 연속 주행 시간 가속 → 가벼운 대화 시작
3. **1:20 부하 제어** — 브레이크 페달 ON → 대화 중지, 그 응답은 측정에서 제외
4. **1:40 지연 증가** — 발표자가 일부러 늦게 대답 → "혹시 졸리세요?" → 무응답 → 경고음
5. **2:20 쉼터** — "12km 앞 ○○졸음쉼터" → "응" → 경유지 추가
6. **2:50 도착** — 속도 0, 기어 P → "등받이를 젖히고 눈을 붙이세요" 안내, 알람(데모는 30초)
7. **3:30 재출발** — 알람 → "등받이를 세워 주세요" → 재출발 체크 → "다음 쉼터는 ○ km 앞"

## 13. 사업 모델과 확대 계획

예상 MAU는 두 가지로 나눠 보고합니다. **보호 주행 MAU**는 월 1회 이상 앱이 켜진 채 장거리·야간 주행을 함께한 사용자이고, **대화 세션 MAU**는 월 1회 이상 대화까지 간 사용자입니다. 정의에 따라 숫자가 약 5배 달라집니다.

| 시나리오 (모두 추정) | 활성화 × 인지 × 설치 × 월 활성 | 2027년 말 (Pleos 약 46만 대) | 2030년 말 (약 340만 대) |
| --- | --- | --- | --- |
| Low | 0.30 × 0.20 × 0.20 × 0.15 = 0.18% | 약 800명 | 약 6천 명 |
| Base | 0.50 × 0.30 × 0.30 × 0.25 = 1.1% | 약 5,200명 | 약 3.8만 명 |
| High (현대 기본 추천·번들) | 0.60 × 0.50 × 0.50 × 0.40 = 6.0% | 약 2.8만 명 | 약 20만 명 |

리텐션은 매일 쓰는 앱의 기준 대신 **다음 장거리 주행에서 다시 켜지는지**로 정의합니다. 빈도 약점은 장거리 자동 대기, 명절 캠페인, 휴식포인트 보상으로 보완합니다.

| 수익 모델 | 구조 | 타당성 |
| --- | --- | --- |
| 현대 번들·기본 추천 | 무료 안전 기능, 앱마켓 수익 배분이나 개발 계약 | 가장 높음 |
| 도로공사 협력 | 위드라이브 휴식포인트 연동(도로공사가 2026년 운영 중, 현재 Wakeon과 연결 없음), 명절 캠페인 | 높음(홍보), 금액은 작음 |
| 휴게소 F&B 쿠폰 | 휴식 도착 시 커피 쿠폰 | 중 |
| 보험 연계 | 동의 기반 ‘휴식 준수’ 점수 | 중\~낮음(졸음 특화 상품 없음) |
| 법인 차량 구독 | 대당 월 3\~5천 원 | 낮음(현재 규모) |
| 소비자 구독 | 월 1\~3천 원 | 가장 낮음 |

**현대에게 주는 가치:** 경고 뒤 공백을 메워 안전 브랜드 이야기를 만들고, Pleos 참여 지표를 높이고, 동의를 받은 휴식 데이터를 쌓습니다.

**확대 순서:** 1단계 그랜저·아반떼 장거리 운전자 + 도로공사 협력 → 2단계 Pleos 탑재 차종 확대 → 3단계 법인 차량 전용 모델 → 4단계 해외(북미는 음성 전용 설계가 이점, EU는 DDAW 의무라 보완층 포지셔닝이 분명) → 5단계 Pleos가 상용차에 들어갈 경우 트럭(미확인).

## 14. 결정 기록과 출처

기획 실무진(PM·PO·서비스기획자·사업전략)과 Pleos 개발자가 함께한 역할극 회의에서 정한 내용입니다. 익명 투표는 1차 평균 +2.6에서 2차 +5.4로 올랐고, 레드팀(사업전략)은 반대 의견을 기록하고 합의를 따르기로 했습니다.

| ID | 안건 | 결정 |
| --- | --- | --- |
| D1 | 주행 중 작동 범위 | ‘허가 시 모드’와 ‘축소 모드’를 모두 설계, 허가 시 모드가 기본안. 카테고리는 모빌리티 서비스 |
| D2 | 졸음 의심 판정 | 본인 평소 속도 기준 + 여러 신호 종합. 2초·3초는 임시값 |
| D3 | 대화 형식 | 정답 있는 질문 + 가벼운 대화(속도 측정용). AI 자유 대화는 P2 |
| D4 | 경고 방식 | 경고음 3단계. 진동 제외. 실내 조명은 Vehicle Control이 열리면 추가(D13) |
| D5 | 도착 후 분기 | 휴식 기본값. 몸 깨우기는 회복 단계(음성 스트레칭). 전화·노래는 P2 |
| D6 | 주차 판단 | 기어 P + 속도 0 + (쉼터 도착 신호 또는 근접) |
| D7 | 첫 타깃 | 장거리·야간 운전자. MAU는 두 가지 정의로 병기 |
| D8 | MVP 범위 | 12장의 서류·데모 범위와 중단 조건 승인 |
| D9 | 데이터 정책 | 음성 원본 저장 안 함, 기기 내 처리 우선, 위치는 서버로 보내지 않음 |

**D10 와이어프레임 제안 반영 (2026-11-08):** 와이어프레임 v0.1 검토에서 나온 제안 14개(7장 A1–A14)를 요구사항에 넣고, 6장 4·5단계와 F7에서 겹치던 ‘본인 응답’ 처리를 ‘1단계 알림음 후 바로 쉼터 제안’으로 정리했습니다.

**D11 서비스 이름 (2026-11-10):** Wakeon으로 확정했습니다. 화면과 문서에는 Wakeon으로 쓰고, 음성 안내와 호출어에서는 '웨이크온'으로 읽습니다.

**D12 범위 조정 (2026-11-10):** F16을 삭제하고 첫 타깃을 장거리·야간 자가용 운전자로 좁혔습니다. F16 번호는 다시 쓰지 않습니다.

**D13 플랫폼 권한 반영 (2026-11-12):** Pleos 콘솔을 확인해 보니 Vehicle Control(시트·조명·공조 제어), FusedLocation, TextToSpeech·SpeechToText가 ‘준비 중’입니다. 그래서 v1은 차량 제어 없이 음성 안내로 휴식을 돕고(F13 보류, 와이어프레임은 제어 없는 휴식 화면이 기본), 위치는 NaviHelper와 안드로이드 위치로, 음성은 Pleos SDK를 먼저 쓰되 안 되면 안드로이드 기본 음성으로 바꿉니다. 사용 가능한 Vehicle State(기어·속도)와 NaviHelper(경로·경유지)로 핵심 흐름은 그대로 시연합니다.
