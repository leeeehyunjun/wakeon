## 1. 이야기

박준호(41), 금요일 밤 9시 서울에서 부산 본가까지. 퇴근 후 4시간 30분 운전.

꼭 보여야 할 5장면: ① 출발 전 체크로 "평소 1.0초" 기억 ② 대답이 2.8초로 늦어짐 ③ "괜찮아" → 무응답 → 단계적 경고 ④ "응" 한 마디로 쉼터가 경유지 ⑤ 도착하면 "등받이를 젖히고 눈을 붙이세요".

## 3. 시연 모드 신호 (adb broadcast)

앱 패키지 `com.wakeon.app`, 액션 `com.wakeon.app.DEMO`. 시연 신호가 한 번이라도 들어오면 그 세션은 시연 모드가 되고, 해당 값은 실제 Vehicle SDK 값보다 우선한다. 화면에는 아무 표시도 하지 않는다(로그에만 `demo=true`).

```
adb shell am broadcast -a com.wakeon.app.DEMO -p com.wakeon.app --es gear D --ei speed 98
```

띄어쓰기가 있는 대답은 **작은따옴표로 한 번 더 감싼다**. adb가 기기 셸에서 띄어쓰기로 다시 쪼개, 감싸지 않으면 "네,"까지만 들어가고 뒤의 값도 사라진다.

```
adb shell am broadcast -a com.wakeon.app.DEMO -p com.wakeon.app --es answer "'네, 한 마리요.'" --ei latencyMs 1200
```

| extra | 형식 | 뜻 |
| --- | --- | --- |
| `gear` | `P` `R` `N` `D` | 기어 |
| `speed` | int (km/h) | 속도 |
| `brake` | `true`/`false` (`--ez`) | 브레이크 페달 |
| `turn` | `L` `R` `OFF` | 방향지시등 |
| `navVoice` | `--ez` | 내비 안내 음성 재생 중(고부하) |
| `driveMin` | int | 연속 주행 시간을 이 값(분)으로 설정 |
| `clock` | `"HH:mm"` | 시연 시각(트리거의 시간대 판정과 화면 시각 표시에 씀) |
| `answer` | string | 다음 듣기 창에서 이 말을 사용자 대답으로 인식한 것으로 처리. `__none__`이면 무응답 |
| `latencyMs` | int | 위 대답의 응답 시간(ms). 앱은 TTS 종료 후 이만큼 기다렸다가 대답을 처리한다 |
| `routeKm` | float (`--ef`) | 시연 경로에서 현재 위치(출발점부터 km) |
| `arrive` | `--ez true` | 경유지 도착 판정 강제 |
| `timeScale` | float (`--ef`) | 앱 타이머 배속(문항 간격·라운드 간격·휴식). 무응답 5초·경고 5초·제안 대기 10초는 영상에서 보여야 하니 배속하지 않는다 |
| `restSec` | int | 휴식 길이를 초로 덮어씀(시연 30) |
| `reset` | `--ez true` | 세션·기준선·카운터 초기화, S-01로 |
| `c2`, `c3` | `--ez` | 트리거 C2(야간)·C3(시속 70km 10분) 켜기/끄기. 홈 화면 토글과 같다. 시연은 시안 W-02처럼 `c3 false` |

`answer`를 미리 큐에 넣어 두면 순서대로 쓴다(질문 하나에 하나). **시연 모드에서는 마이크와 STT를 열지 않는다.** 큐가 비었거나 `__none__`이면 마이크 없이 듣기 창(5초)만큼 기다린 뒤 무응답으로 처리한다(2026-11-13 결정). 실제 모드(시연 신호가 없는 세션)는 실제 음성 인식을 쓴다.

## 4. 시연 경로 데이터

`app/src/main/assets/demo_route.json`에 둔다. 경부고속도로 서울→부산을 단순화한 1차원 경로다. 실시간 공공데이터 연동은 2차.
쉼터 3곳은 한국도로공사 공공데이터에서 경부선 부산 방향, 서울 기점 약 230km 근처에서 졸음쉼터 → 휴게소 → 졸음쉼터가 사이에 다른 시설 없이 이어지는 곳을 골랐다(확인 2026-11-13).

| 순서 | 이름 | 서울 기점 km | 이정(부산 기점) | 출처 |
| --- | --- | --- | --- | --- |
| 1 | 선기졸음쉼터 (경북 구미시 도량동) | 238.0 | 178.0 | [졸음쉼터 설치현황](https://www.data.go.kr/data/15043710/fileData.do), 좌표 [전국졸음쉼터표준데이터](https://www.data.go.kr/data/15028203/fileData.do) |
| 2 | 칠곡휴게소 (부산 방향) | 약 258.0 | 약 158.0 (추정) | [휴게소 현황](https://www.data.go.kr/data/15164198/fileData.do), 좌표 [휴게소 위치정보 API](https://data.ex.co.kr/openapi/locationinfo/locationinfoRest) |
| 3 | 하빈졸음쉼터 (대구 달성군 하빈면) | 270.0 | 146.0 | 졸음쉼터 설치현황, 전국졸음쉼터표준데이터 |

- 서울 기점 km = 416 − 이정(경부선 이정은 부산 기점). 휴게소 자료에는 이정이 없어, 칠곡휴게소는 앞뒤 졸음쉼터(석적 162.6, 하빈 146.0)의 이정과 좌표로 위치를 추정했다.
- 230km에 가장 가까운 대신졸음쉼터(226km)는 바로 다음 시설이 선기졸음쉼터라 "쉼터 → 휴게소 → 쉼터" 순서가 안 맞아 고르지 않았다.
- 장면 14에서 현재 `routeKm`=226 → 선기졸음쉼터 12km, 다음 후보 칠곡휴게소 32km.
- 장면 16에서 `routeKm`=237 → 1km 전 안내.
- 장면 21의 "다음 쉼터 32km"는 선기졸음쉼터(238) 기준 다음 졸음쉼터 하빈(270).
- 도착 시각·"약 8분"은 현재 속도로 계산한 값(시연 시각 기준)이고, 장면표의 숫자와 ±1분은 괜찮다.

## 5. 녹화용 스크립트

`demo/run_scenario.sh`가 위 장면을 순서대로 보낸다. 장면 사이 대기 시간은 앱의 TTS 길이를 고려해 넉넉히 두고, 각 장면 시작 때 터미널에 `# 장면 N · 화면 W-xx`를 출력한다.

녹화는 **에뮬레이터 자체 화면 녹화**(`adb emu screenrecord`, `demo/record.sh`)로 화면과 기기 안 소리를 함께 담는다(2026-11-13 결정, `docs/DECISIONS.md`).
- scrcpy는 이 차량용 에뮬레이터의 소리를 녹음하지 못한다(소리가 차량용 출력 버스로만 나가 무음으로 녹음됨).
- **녹화할 때는 에뮬레이터를 `bash demo/start_emulator.sh --record`로 켠다.** 소리를 맥 스피커 대신 파일로 내보내는 모드다(녹화 중 맥 스피커로는 소리가 안 나옴). 맥 스피커로 재생하면서 녹화하면 녹화본의 목소리에도 갈라짐이 남는다(2026-11-13 확인, PLEOS_NOTES 12장). 연습·확인할 때는 `bash demo/start_emulator.sh`(맥 스피커).
- `start_emulator.sh`는 차량 음량(음성·알람 그룹)을 40/45로 맞춘다. 녹화 원본이 바로 적당한 크기(최고 약 −6.6dBFS)라 따로 키우지 않는다.
- `bash demo/record.sh stop`이 영상(mp4, 소리 AAC 320k)과 소리(wav)를 만든다. 소리 가공은 말 사이를 0으로 만드는 노이즈 게이트 하나뿐이다(게인·리미터·loudnorm 없음). 소리가 작으면 녹화 모드가 아니었다고 알려 준다.
- 에뮬레이터는 맥 마이크 입력을 끈 채로 켠다(`demo/start_emulator.sh`가 `avd hostmicoff`).
- 녹화 뒤 `python3 -I tools/click_check.py 소리.wav`로 검사한다. 기준: 1초마다 순간 잡음 ≤ 0.5%, 말 사이 무음 RMS ≤ 2.
- 녹화 전에 한 번 말을 시켜 TTS 엔진을 깨운다(첫 문장만 몇 초 늦음).
- 화면 확인: `bash demo/capture_screens.sh`가 이 장면표를 시연 신호로 따라가며 화면마다 앱 창을 `docs/shots/W-xx.png`로 찍는다(정차 화면은 2:0 가로 창, 주행 화면은 1:1 세로 창으로 바꿔 가며). 대답은 묻기 전에 미리 넣는다(시연 모드는 듣기 창이 열릴 때 대답이 없으면 5초 무응답).
