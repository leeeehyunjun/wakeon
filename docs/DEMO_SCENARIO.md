## 3. 시연 모드 신호 (adb broadcast)

앱 패키지 `com.wakeon.app`, 액션 `com.wakeon.app.DEMO`. 시연 신호가 한 번이라도 들어오면 그 세션은 시연 모드가 되고, 해당 값은 실제 Vehicle SDK 값보다 우선한다. 화면에는 아무 표시도 하지 않는다(로그에만 `demo=true`).

```
adb shell am broadcast -a com.wakeon.app.DEMO -p com.wakeon.app --es gear D --ei speed 98
```

| extra | 형식 | 뜻 |
| --- | --- | --- |
| `gear` | `P` `R` `N` `D` | 기어 |
| `speed` | int (km/h) | 속도 |
| `brake` | `true`/`false` (`--ez`) | 브레이크 페달 |
| `turn` | `L` `R` `OFF` | 방향지시등 |
| `navVoice` | `--ez` | 내비 안내 음성 재생 중(고부하) |
| `driveMin` | int | 연속 주행 시간을 이 값(분)으로 설정 |
| `clock` | `"HH:mm"` | 시연 시각(트리거의 시간대 판정과 화면 시각 표시에 씀) |
| `answer` | string | 다음 듣기 창에서 이 말을 사용자 대답으로 인식한 것으로 처리. `__none__`이면 무응답 |
| `latencyMs` | int | 위 대답의 응답 시간(ms). 앱은 TTS 종료 후 이만큼 기다렸다가 대답을 처리한다 |
| `routeKm` | float (`--ef`) | 시연 경로에서 현재 위치(출발점부터 km) |
| `arrive` | `--ez true` | 경유지 도착 판정 강제 |
| `timeScale` | float (`--ef`) | 앱 타이머 배속(문항 간격·라운드 간격·휴식). 무응답 5초·경고 5초·제안 대기 10초는 영상에서 보여야 하니 배속하지 않는다 |
| `restSec` | int | 휴식 길이를 초로 덮어씀(시연 30) |
| `reset` | `--ez true` | 세션·기준선·카운터 초기화, S-01로 |

`answer`를 미리 큐에 넣어 두면 순서대로 쓴다(질문 하나에 하나). 큐가 비어 있으면 실제 음성 인식(가능하면) 또는 무응답으로 처리한다.

## 4. 시연 경로 데이터

`app/src/main/assets/demo_route.json`에 둔다. 경부고속도로 서울→부산을 단순화한 1차원 경로다. 실제 공공데이터 연동은 2차.

```json
{
  "route": "경부고속도로 · 부산 방향",
  "totalKm": 400,
  "restAreas": [
    { "name": "○○졸음쉼터", "type": "drowsy_shelter", "km": 164.0, "exit": "오른쪽" },
    { "name": "△△휴게소", "type": "service_area", "km": 179.0, "exit": "오른쪽" },
    { "name": "다음 졸음쉼터", "type": "drowsy_shelter", "km": 202.0, "exit": "오른쪽" }
  ]
}
```

- 장면 14에서 현재 `routeKm`=152 → ○○졸음쉼터 12km, △△휴게소 27km.
- 장면 16에서 `routeKm`=163 → 1km 전 안내.
- 장면 21의 "다음 쉼터 38km"는 쉼터(164) 기준 다음 졸음쉼터(202).
- 도착 시각·"약 8분"은 현재 속도로 계산한 값(시연 시각 기준)이고, 장면표의 숫자와 ±1분은 괜찮다.

## 5. 녹화용 스크립트

`demo/run_scenario.sh`가 위 장면을 순서대로 보낸다. 장면 사이 대기 시간은 앱의 TTS 길이를 고려해 넉넉히 두고, 각 장면 시작 때 터미널에 `# 장면 N · 화면 W-xx`를 출력한다. 녹화는 Android Studio 에뮬레이터의 화면 녹화(⋯ → Record and Playback) 또는 `adb shell screenrecord`(3분 제한, 여러 번)로 한다. TTS 소리가 함께 녹음되는지 첫 녹화 때 확인한다.
