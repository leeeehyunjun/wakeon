# Wakeon 기능명세서

Nov 9, 2026 · @어식스트

## 0. 문서 안내

이 문서는 Wakeon의 동작을 상태·조건·숫자로 정의한다. 개발자는 이 문서만 보고 구현할 수 있어야 하고, 디자이너는 모든 화면 상태를 빠짐없이 그릴 수 있어야 한다. 화면의 모양은 피그마가, 동작은 이 문서가 기준이다.

| 독자 | 먼저 읽을 곳 | 이유 |
| --- | --- | --- |
| 앱 개발 | 4 상태 머신 → 5 판단 로직 → 6 기능 상세 → 10 로그 | 언제 무엇이 바뀌는지와 그 기준값 |
| 디자인 | 8 화면 대응표 → 6 기능 상세의 '출력' → 7 음성 대화 | 상태마다 그려야 할 화면과 말 |
| 기획·QA | 1 범위 → 6 수용 기준 → 12 예외 | 무엇을 만들고 무엇으로 통과를 판단하는지 |

**표기 규칙**

| 표기 | 뜻 | 예 |
| --- | --- | --- |
| F-xx | 기능 | F-05 졸음 위험 판단 |
| S-xx | 앱 상태 | S-03 대화 중 |

## 1. 개요와 범위

Wakeon은 졸음 위험이 있는 운전자에게 차가 먼저 말을 걸고, 가장 가까운 졸음쉼터를 경유지로 넣고, 15분 휴식과 재출발 확인까지 이어 주는 Pleos Connect 앱이다. 성공의 기준은 하나, **앱이 유도한 휴식 완료 건수**(앱 제안으로 쉼터에 도착해 기어 P로 15분 이상 머문 건수)다. 대화 턴 수나 경고 횟수는 목표가 아니다.

**만드는 것과 만들지 않는 것**

| 구분 | 항목 |
| --- | --- |
| P0 (12/3 시연 필수) | F1 주행 상태 인식과 화면 제한 · F2 출발 전 체크 · F3 위험 맥락 트리거 · F4 음성 대화 루프 · F5 응답 시간과 기준선 · F6 의심 판정 · F7 단계적 경고 · F8 쉼터 탐색과 경유지 · F9 도착 판단과 휴식 제안 · F10 휴식 타이머 · F11 재출발 체크 · F12 동의와 데이터 최소화 |
| P1 (MVP) | F13 시트·조명·공조 휴식 제어(보류, 권한이 열리면) · F14 몸 깨우기 루틴 · F15 도로공사 휴식포인트 안내 · F17 질문 다양화 · F18 글레오 진입점 · F19 주행 후 평가 |
| 제외 (v1) | F20 전화 · F21 노래 · F22 AI 자유 대화 · F23 보험 리포트 |
| 하지 않음 (비목표) | 졸음·수면장애 진단, 카메라·시선 추적, 운전 차단, 자동 긴급 전화, DAW·NCAP 동등 주장, 목소리로 사람 식별, 음성 원본 저장, 주행 중 영상, 차량 진동 |

기능 ID는 PRD와 같다. 빠진 번호(F16)는 다시 쓰지 않는다.

**운영 모드** — 플랫폼 답변과 사용자 동의에 따라 앱은 세 모드 중 하나로 돈다. 모드는 앱 시작 때 정해지고, 주행 중에는 바뀌지 않는다.

| 모드 | 조건 | 달라지는 것 |
| --- | --- | --- |
| 기본 모드 | 동의 완료 + 주행 중 앱 선발화 허용(T1) | 이 문서의 모든 동작 |
| 축소 모드 | 동의 완료 + T1 불허 | 주행 중 대화는 사용자가 "웨이크온 켜줘"로 시작할 때만. F3 트리거는 화면 한 줄 예고로만 표시(W-04b). 쉼터 제안·휴식·재출발은 기본 모드와 같음 |
| 정차 전용 모드 | 필수 동의 거절 | 마이크·위치를 쓰지 않는 기능만: 휴식 타이머, 쉼터 목록(수동 선택). 주행 중 동작 없음(W-02b) |

차량 제어(시트·조명·공조)는 Pleos 콘솔의 Vehicle Control이 ‘준비 중’(2026-11-12 확인)이라 v1에서는 어느 모드든 음성 안내로 동작한다(F13 보류, 휴식 화면 W-13). 권한이 열리면 켜는 확장 화면은 E-6이다.

**용어**

| 용어 | 정의 |
| --- | --- |
| 주행 중 | 기어가 P가 아니거나 속도가 0km/h보다 크다. 그 외는 정차 중 |
| 세션 | 기어 P→D 전환부터, 기어 P가 10분 이상 이어지거나 앱이 종료될 때까지의 한 번의 주행. 앱이 시작한 휴식은 세션을 끝내지 않는다 |
| 연속 주행 시간 | 마지막 리셋(5장) 이후 주행 중이었던 시간의 합. 10분 미만 정차는 빼지 않고 계속 셈다 |
| 응답 시간 | 앱의 질문 음성 출력 종료 시각 → 사용자 첫 발화 시작 시각(ms) |
| 유효 응답 | 기준선·판정 계산에 넣는 응답. 고부하 중 응답, 인식 실패, 무응답은 제외 |
| 기준선 | 깨어 있을 때의 본인 평소 응답 시간. 유효 응답 3\~5개의 중앙값(3개로 확정, 5개까지 갱신) |
| 고부하 상태 | 운전이 바쁜 순간. 브레이크 페달, 방향지시등, 내비 안내 음성, 글레오 동작, 통화 중 하나라도 켜짐 |
| 쉼터 | 졸음쉼터(공공데이터) 우선, 없으면 휴게소 |
| 휴식 완료 | 앱이 시작한 휴식에서 기어 P가 15분 이상 이어진 것. North Star 이벤트 |

## 2. 플랫폼 전제

기준 화면은 Connect-S 17″(2560×1440, 16:9)이고, 주행 중에는 세로 창 840×1184 하나만 쓴다. 가장 큰 불확실성은 주행 중 앱이 먼저 말을 걸 수 있는지(T1)이며, 답에 따라 기본 모드와 축소 모드가 갈린다.

**화면 규격** \[확정: Pleos 공식 디스플레이 규격표 · 단위 dp\]

| 항목 | 17″ (기준) | 14.6″ | 12.9″ |
| --- | --- | --- | --- |
| 화면 | 2560×1440 | 2048×1152 | 1920×1080 |
| DPI (1dp = ?px) | 160 (1dp = 1px) | 200 (1dp = 1.25px) | 160 (1dp = 1px) |
| 상태바 / GNB 높이 (규격표에서 역산) | 96 / 160 | 76 / 128 | 84 / 141 |
| Driving view 폭 (시스템, 앱 사용 불가 · 역산) | 840 | 672 | 628 |
| 앱 2개 1:1 → 세로 창 | 840×1184 ×2, 사이 20(창 손잡이) | 672×948 | 628×855 |
| 앱 1개 2:0 → 가로 창 | 1700×1184, 오른쪽 20(창 손잡이) | 1360×948 | 1274×855 |

- **표 읽는 법:** 공식 규격표에 있는 값은 화면 해상도, DPI, 가로 창, 세로 창 넷이다. 상태바·GNB 높이와 Driving view 폭은 표에서 역산한 값이다(17″: 1440 − 1184 = 256 = 96 + 160, 2560 − 1700 = 860 = 840 + 20).
- **디자인 기준:** 17″는 160dpi라 1dp = 1px이다. 피그마에서 가로 창은 **1700×1184**, 세로 창은 **840×1184** 프레임으로 그린다. 앱이 그릴 수 있는 곳은 이 창 안뿐이고, 창 바깥(Driving view·상태바·GNB·창 손잡이)은 시스템이 그린다. 창 안 여백(가로 창 64, 세로 창 57)은 Wakeon이 정한 값이다.
- **에뮬레이터와의 차이:** 공식 에뮬레이터 v2.1.0(2560×1440, 160dpi)에서는 창이 가로 1682×1210, 세로 841×1210으로 잡힌다(상태바 90, GNB 140, Driving view 853; 다른 참가 팀 공개 저장소의 실측 3건). 디자인은 공식 규격표를 따르고, 앱은 받은 창 크기에 맞춰 늘고 줄게 만든다. 고정 px로 배치하지 않는다. 시연(12/3) 전에 에뮬레이터에서 `adb shell dumpsys window`로 실제 창 크기를 확인한다.
- **범위 밖:** Connect-W·WF(창 800\~1640 × 800\~1400)는 v1 대상이 아니다.

**창 사용 규칙**

- 주행 중: Wakeon 세로 창 + 내비 세로 창(1:1). 기본 내비는 닫을 수 없으므로 주행 화면은 항상 세로 레이아웃으로 설계한다.
- 정차 중 설정·휴식·재출발 화면: 가로 창(2:0). 사용자가 1:1로 되돌리면 같은 내용을 세로 레이아웃으로 보여 준다. 모든 정차 화면은 두 방향을 모두 갖는다. 세로 버전은 피그마 섹션 G에 있고 ID 끝에 -V를 붙인다(예: W-02-V).
- 두 창의 좌우 위치는 사용자가 바꿀 수 있다. 화면 문구와 레이아웃은 왼쪽·오른쪽 위치에 기대지 않는다.
- 전체 화면(3:0)은 후방 카메라 같은 시스템 예외만 가능하다. Wakeon은 쓰지 않는다.

**주행 중 제약** (F1, SR2, SR7)

- 주행 중에는 영상, 키보드, 시트 제어, 설정 변경을 쓰지 않는다.
- 화면 문구는 한 덩어리 3줄, 120자 이하. 화면을 봐야만 끝나는 과업은 0개다. 버튼은 두되 음성으로 같은 일을 할 수 있어야 한다.
- 핵심 문구 61px 이상, 일반 문구 33px 이상, 터치 영역 139px 이상(17″ 기준, 다른 크기는 비율대로 줄인다). 공식 기준은 글자 실제 높이 핵심 5mm·보조 3mm 이상이고 17″에서 1mm는 약 6.8px다. 61px 글자는 한글 실제 높이가 약 7.5mm, 33px는 약 4mm라 공식 기준을 넘는다.

**SDK·API 매핑** — Pleos 콘솔의 SDK는 Vehicle State, NaviHelper, FusedLocation, TextToSpeech, SpeechToText, Vehicle Control 6종이다. 2026-11-12 기준 Vehicle State와 NaviHelper만 ‘사용 가능’이고 나머지는 ‘준비 중’이다. Wakeon은 사용 가능한 둘을 중심으로 만들고, 음성은 Pleos SDK를 먼저 쓰되 막히면 안드로이드 기본 음성으로, 위치는 NaviHelper와 안드로이드 기본 위치로 대신한다. 차량 제어는 v1에서 빠진다.

| 필요한 값·동작 | 쓸 API | 쓰는 기능 | 상태 |
| --- | --- | --- | --- |
| 기어(P/R/N/D) | Vehicle · AAOS 표준 속성 `CURRENT_GEAR` | F1, F2, F9, F11 | 읽기 가능. 공모전 허용은 확인 필요(T2) |
| 속도 | Vehicle · AAOS 표준 속성 `PERF_VEHICLE_SPEED`, 보조로 안드로이드 위치 속도 | F1, F3, F9 | 읽기 가능(T2 동일) |
| 브레이크 페달 | Vehicle · Brake 도메인(페달 상태) | F4 멈춤, F7 급제동, E-3 등받이 안내 | 페달만 있음. 주차 브레이크는 없음 |
| 방향지시등 | AAOS 표준 속성 `TURN_SIGNAL_STATE` | F4 멈춤 | Pleos 노출 여부 확인 필요(T2) |
| 내비 경유지 추가·도착 | NaviHelper 경유지 API, `onWayPointArrived` | F8, F9 | 경유지 최대 2개. 도착 콜백은 "호출될 수 있음" 수준 |
| 내비 안내 음성 재생 여부 | 안드로이드 오디오 포커스 변화 | F4 멈춤, F8 안내 생략 | 포커스 상실로 간접 감지 |
| 위치·진행 방향 | NaviHelper 경로 정보(현재 위치), 보조로 안드로이드 기본 위치 | F8, F9 | 가능. FusedLocation은 ‘준비 중’이라 쓰지 않음(T19) |
| 음성 출력 | TextToSpeech (재생 시작·종료 콜백). 막히면 안드로이드 TextToSpeech | 전체 | 콘솔 ‘준비 중’, 에뮬레이터에서 확인(T18). 주행 중 선발화는 T1 |
| 음성 인식 | SpeechToText (`ON_DEVICE`, `onUpdatedRms`, 끝점 검출). 막히면 안드로이드 SpeechRecognizer | F2, F4, F5, F6 | 콘솔 ‘준비 중’(T18). "소리 없음"과 "인식 실패" 구분은 확인 필요(T10) |
| 좌석 착석·벨트 | Vehicle · Seat (`getCurrentSeatOccupancy`) | 참고 | 읽기 가능 |
| 등받이 각도 제어 | Vehicle · Seat 제어(`CONTROL_CAR_*` 계열) | F13, F14 | Vehicle Control ‘준비 중’, v1 제외(T3) |
| 실내 조명 색·밝기 | Vehicle · Light | F7, F13 | Vehicle Control ‘준비 중’, v1 제외(T3, T4) |
| 공조 외기 전환 | Vehicle · HVAC | F13 | Vehicle Control ‘준비 중’, v1 제외(T3) |
| 운전자 주의 경고(DAW) 신호 | 시스템 전용 | 쓰지 않음 | 불가(T8) |

음성 인식과 합성은 기기 안 처리(`ON_DEVICE`)를 기본으로 한다. 네트워크가 없어도 모든 P0 기능이 동작해야 한다. Pleos 음성 SDK가 막히면 같은 인터페이스 뒤에서 안드로이드 기본 TextToSpeech·SpeechRecognizer로 바꿔 끼운다. 이때 네트워크 없는 한국어 인식이 되는지 에뮬레이터에서 먼저 확인한다(T18).

## 3. 시스템 구성

앱은 모듈 7개와 설정 파일 하나로 나뉜다. 판단과 전이는 상태 머신 한 곳에서만 일어난다. 다른 모듈은 이벤트를 보내고 요청을 수행할 뿐, 스스로 상태를 바꾸지 않는다.

&#91;embedded content: 시스템 구성 · SDK 5종과 앱 모듈 7개\]

- 차량 상태 모니터가 만드는 두 값, "주행 중"과 "고부하"는 모든 상태의 가드 조건이다.
- 대화 엔진은 상태 머신의 요청으로만 말한다. 고부하 이벤트가 오면 상태 머신을 거치지 않고 바로 멈춘다(0.25초 규칙 때문).
- 휴식 제어는 차량 원래 값을 저장소에 먼저 쓴 뒤에야 제어를 시작한다.

## 4. 상태 머신

## 5. 졸음 위험 판단 로직

Wakeon은 졸음을 감지한다고 주장하지 않는다. 두 단계로 판단한다. 먼저 위험 맥락이 있으면 대화를 시작하고, 다음으로 응답이 본인 기준선보다 나빠지면 직접 묻는다. "졸리지 않다"는 판정은 어느 단계에서도 내리지 않는다.

### 5-1. 입력 신호

| 신호 | 출처 | 갱신 | 쓰는 곳 |
| --- | --- | --- | --- |
| 기어 | Vehicle | 바뀔 때 | 모든 상태 전이 |
| 속도 | Vehicle (보조: 안드로이드 위치) | 1초 | 고속 지속 트리거, 도착 판단 |
| 브레이크 페달 · 방향지시등 | Vehicle | 바뀔 때 | 고부하 판정 |
| 내비 안내 음성 · 글레오 · 통화 | 오디오 포커스 · 시스템 상태 | 바뀔 때 | 고부하 판정 |
| 현재 시각 | 기기 | 1분 | 시간대 트리거 |

| 실내 말소리 유무 | STT 음량(RMS)만, 내용은 듣지 않음 | 질문 직전 | 질문 시작 미루기 |

### 5-2. 연속 주행 시간

- **늘어남**: 주행 중인 동안 1초씩.
- **0으로 리셋**: ① 휴식 완료(앱 휴식에서 P 15분) ② 앱 휴식이 아닌 정차에서 기어 P가 10분 이상 이어짐(휴게소 등).
- **리셋하지 않음**: 10분 미만 정차(A3), 정체 중 대화 멈춤, 앱 휴식이 15분 전에 끝남(E-3). E-3은 휴식 전 값에서 이어서 셈다.

### 5-3. 위험 맥락 트리거 (대화를 시작할지)

아래 조건 중 하나가 참이고 고부하 상태가 아니면, 기본 모드는 60초 안에 첫 질문을 시작한다.

| ID | 조건 | 기본 | 사용자가 끌 수 있나 |
| --- | --- | --- | --- |
| C1 | 연속 주행 2시간 이상 | 켜짐 | 불가. 휴식을 권하는 최저선(A1) |
| C2 | 21:00\~06:00 또는 12:00\~15:00에 연속 주행 30분 이상 \[가정: 30분은 이 문서에서 추가한 오경보 방지선\] | 켜짐 | 가능(정차 중에만) |
| C3 | 70km/h 이상 10분 연속 | 켜짐 | 가능(정차 중에만) |
| C4 | 사용자 발화 "웨이크온 켜줘" | 항상 | — (축소 모드의 유일한 시작점) |

- **라운드**: 한 번 시작하면 최대 6문항을 묻고 대기로 돌아간다. 조건이 계속 참이면 20분 뒤 다음 라운드를 시작한다 \[가정\].
- **문항 간격**: 기본 4분(범위 3\~5분). 의심 확인에서 '아니', 미루기 중, E-3 이후에는 3분.
- **강제 제안**: C1과 야간(21:00\~06:00)이 동시에 참이면, 의심 신호가 없어도 첫 라운드가 끝날 때 쉼터 제안(S-08)을 1회 한다. "놓치는 것"을 막기 위한 안전망이다(PRD 11장 위험 1).

### 5-4. 응답 시간과 기준선

- **응답 시간** = STT 첫 발화 시작 시각 − TTS 재생 종료 시각(ms). 사용자가 인식 결과를 고쳐 말해도 첫 발화 시각을 쓴다.
- **유효 응답에서 빼는 것**: 질문\~응답 사이에 고부하가 있었던 응답, 인식 실패, 무응답, 자가 보고 질문(졸림 1\~9)의 응답.
- **기준선 B** = 정답형 질문의 유효 응답 중앙값. 출발 전 체크에서 유효 응답이 3개 이상이면 그 중앙값으로 확정하고, 5개가 될 때까지 주행 초반 대화의 유효 응답을 더해 갱신한다. 3개 미만이면 임시 기준을 쓰고 주행 초반 대화로 3개를 채워 확정한다. 세션마다 새로 잰다.
- **확정 전 임시 기준**: 7일 안에 저장된 지난 기준선이 있으면 그 값을, 없으면 지연 임계값 2,000ms를 쓴다 \[가정: 지난 기준선 사용은 이 문서의 제안\]. PRD의 3초 임시값은 쓰지 않고 2초 하나로 통일한다(13장 T11).

### F4 음성 대화 루프 · P0

대화는 두 가지 일을 한다. 하나는 **운전자를 대화로 깨어 있게 붙잡는 스몰토크**이고, 다른 하나는 그 대답으로 반응 속도를 재는 **측정**이다. 모든 질문은 정답이 있거나 응답 속도를 잴 수 있어야 하고, 운전이 바쁜면 입을 다문다. 대화로 졸음이 없어지지는 않는다. 대화는 쉼터까지 깨어 있도록 돕는 수단이고, 끝은 휴식이다.

**깨우는 스몰토크 원칙**

- **내 이야기로 끌어들인다.** 반려동물·가족·목적지·음식처럼 마음이 가는 주제가 정답 맞히기보다 오래 깨어 있게 한다.
- **대답을 조금씩 길게 끌어낸다.** 예/아니 → 한 단어(이름) → 짧은 문장(어떤 걸 좋아하는지) 순서로, 운전자가 소리 내어 말하는 양을 늘린다.
- **앞에서 들은 걸 기억해 다시 꺼낸다.** ("보리는 몇 살이라고 하셨죠?") 기억을 떠올리게 하는 것 자체가 머리를 쓰게 하고, 그 응답 속도가 측정이 된다.
- **호응은 따뜻하고 짧게.** 핵심 단어를 되받는다("보리, 이름 예쁘네요."). 상태를 판정하지 않는다.
- **줄기 끝에는 머리를 쓰는 가벼운 놀이 하나.** 끝말잇기·셈처럼 바로 답이 나오는 것.
- **출발 전 체크의 답을 이어 쓴다.** 체크에서는 짧게 호응만 하고(30초를 지킴), 주행 중 대화에서 그 답으로 줄기를 연다. 예: 체크 "강아지와 고양이 중에 뭐가 좋아요?" → "강아지" → "강아지 좋죠." / 주행 중 "아까 강아지가 더 좋다고 하셨죠. 키우세요?" → "네, 한 마리요." → "한 마리 키우시는구나. 이름이 뭐예요?" → "보리요." → "보리, 이름 예쁘네요. 보리는 몇 살이에요?" → "세 살." → "세 살이면 한창 뛰어놀 때죠. 보리는 산책 좋아해요?"

| 항목 | 정의 |
| --- | --- |
| 시작 | F3 트리거, 또는 사용자 "웨이크온 켜줘" |
| 처리 (1문항) | 1) 질문 은행에서 한 문항을 고른다(F17). 2) 오디오 포커스를 일시 획득(음악은 음량만 낮춤)하고 TTS를 재생한다. 3) 재생이 끝나면 즉시 STT를 열고 응답 시간 타이머를 시작한다. 4) 인식 결과를 W-05b에 2초 보여 주고, 호응 + 이어지는 질문으로 대화를 잇는다(대화 줄기). 호응은 대답의 핵심 단어를 되받아 말하고("한 마리 키우시는구나.", "보리, 이름 예쁘네요."), 기억형 오답이면 "아, 그러셨구나"("틀렸어요" 금지). 이어지는 질문은 앞 대답에서 나온다(슬롯). 줄기 하나는 2\~3턴, 라운드 하나는 줄기 2\~3개. 호응과 질문은 각각 3초 이하, 사이 0.3초. 응답 시간은 질문이 끝난 때부터 잰다. 5) 응답 기록을 F5·F6에 넘기고 다음 문항까지 기다린다. 6) 라운드 최대 6문항, 화면에 "대화 3/6"처럼 진행을 표시한다 |
| 1차 구현 메모 (개발 중 정함, 2026-11-13) | ① 같은 줄기 안의 다음 질문은 인식 결과 2초 표시 뒤 바로, 줄기 사이는 문항 간격(4분, 단축 3분). ② 줄기가 끝나면 호응만 말하고 다음 줄기는 문항 간격 뒤에 연다. ③ 고부하로 멈추면 말하던 질문은 버리고, 아직 말하지 않은 이어질 질문(호응 포함)은 재개 때 말한다. ④ 반려동물 줄기는 시연대로 4턴(키우세요 → 이름 → 나이 → 산책), 갈래: 고양이, 안 키움("그럼 키운다면 이름을 뭐로 지을래요?"), 모르는 대답("그렇군요." + 다른 질문). ⑤ 1차 주제: 음식·반려동물·목적지·가족·음악. ⑥ 들은 이름·나이 등 슬롯은 세션 메모리에만 둔다(9장). ⑦ 호응과 질문은 한 번의 TTS로 이어 말한다 |
| 멈춤 (S-05) | 고부하 조건 5개 중 하나가 켜지면 0.25초 안에 TTS를 멈추고 STT를 닫는다. 아무 말도 하지 않고 화면 문구만 바꾼다. 진행 중이던 문항은 버리고 다시 묻지 않는다. 조건이 모두 풀리고 10초 뒤 새 문항으로 재개한다. 5분 넘게 멈추면(정체) 라운드를 초기화하고, 연속 주행 시간은 계속 셈다 |

### F17 질문 다양화 · P1

같은 질문이 반복되면 대화가 거슬리고 응답 속도도 학습돼 측정이 흐려진다.

| 유형 | 예 | 정답 판정 |
| --- | --- | --- |
| 셈 | "7 더하기 5는요?", "12 빼기 4는요?" | 숫자 일치. 한글 수사("팔", "여덟")를 숫자로 정규화 |
| 기억 | "점심에 뭐 드셨다고 하셨죠?" | 앞서 들은 답의 핵심 단어 포함. 답은 세션이 끝나면 지운다 |
| 끝말잇기 | "기차!" | 첫 음절이 앞 말의 끝 음절과 같고 2음절 이상. 사전 확인은 하지 않는다 |
| 선택 | "강아지와 고양이 중에 뭐가 좋아요?" | 선택지 2\~5개 중 하나 일치. 응답 속도 측정용 |
| 이어가기 | "한 마리 키우시는구나. 이름이 뭐예요?" (앞 대답 '네, 한 마리요'에서 이어짐) | 말소리가 있으면 유효(속도만 잰). 답의 핵심 단어는 세션 메모리에 두고 다음 호응·기억 질문에 쓴다. 주제별(음식·목적지·음악·날씨·동행) 줄기 템플릿으로 만든다 |

규칙: 같은 문항은 7일 안에 다시 내지 않고, 같은 유형은 연속 두 번 내지 않는다. 7일간 반복 없이 돌리려면 최소 130문항이 필요하다(하루 3라운드 × 6문항 × 7일 = 126) \[가정\]. 질문은 앱에 내장하고, 출제 이력만 기기에 7일 보관한다.

### F18 글레오 진입점 · P1

글레오 AI에 외부 앱 호출을 등록할 수 있으면 "웨이크온 켜줘" → 대화 시작(C4), "졸음쉼터 안내해 줘" → S-08을 등록한다. 현재 글레오의 외부 앱 연동은 공개되지 않았다. 등록이 안 되면 축소 모드의 시작점이 사라지므로 대안이 필요하다(13장 T15).

평가는 탭 한 번, 이유는 고르기만 한다. "거슬렸어요"의 이유는 다음 버전의 대화 빈도와 경고 강도를 조정하는 유일한 사용자 신호다.

## 7. 음성 대화 명세

주행 중 사용자와 Wakeon의 접점은 거의 전부 소리다. 그래서 대사는 화면 문구처럼 ID를 붙여 관리하고, 대사를 바꾸려면 이 표를 먼저 바꾼다. 화면 문구는 항상 TTS와 같은 문장이다. 단, 서비스 이름은 화면에 Wakeon, 음성(TTS·호출어)에는 ‘웨이크온’으로 쓴다.

### 7-1. 발화 규칙 (SR3)

- 한 문장은 3초 이하, 질문은 한 번에 1개, 선택지는 2\~5개.
- 주행 중에는 한 번에 한 문장. 단, 대화(F4)는 호응 1 + 질문 1을 이어 말한다. 정차 중에는 두 문장까지 이어 말할 수 있다(사이 0.5초).
- 다음에 할 행동을 말한다. "위험합니다" 대신 "쉼터로 안내할게요".
- 판정·진단·안심 표현은 쓰지 않는다. 금지 목록은 아래 7-5.
- 갑자기 말을 걸지 않도록 대기 화면에서 "18분 뒤"처럼 미리 알린다.

### 7-4. 타이밍과 오디오 우선순위

| 항목 | 값 |
| --- | --- |
| 질문 후 듣기 창 | 말소리가 없으면 5초 뒤 무응답, 말이 시작되면 끝점 검출까지(최대 8초) \[가정\] |
| 인식 결과 화면 표시 | 2초 후 사라짐 |
| 제안·선택 응답 대기 | 10초 (S-08, S-11, S-15) |
| 고부하 감지 → TTS 중지 | 0.25초 이내 |

오디오는 아래 순서로 양보한다. 위의 것이 시작되면 아래의 Wakeon 소리는 0.25초 안에 멈추거나 낮아진다.

1. 시스템 안전 알림(차량 경고, 후방 카메라 등)
2. 통화
3. 내비 안내 음성
4. 글레오
5. Wakeon 경고음(S-07). 내비 안내와 겹치면 멈추지 않고 1단계 음량으로 낮춘다 \[가정\]
6. Wakeon TTS
7. 음악·미디어(Wakeon이 말하는 동안 음량만 낮춤)
